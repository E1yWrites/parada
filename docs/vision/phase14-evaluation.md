# Phase 14 — Testing + Accuracy Evaluation

Measured on 2026-09-14 (local, UTC+8) on the `parada-crossplatform` working tree with
the Phase 13 integration work applied. Every number below is copied from a generated
artifact under `services/vision/evaluation/results/`; nothing is estimated.

**Scope statement.** This is a *characterisation* of the Phase 11 pipeline
(classical OpenCV plate-region detector + EasyOCR) on a controlled, project-owned
synthetic dataset plus a live camera-connectivity probe. It is **not** a production
accuracy claim: no real vehicle photographs were available under a usage permission,
so real-world lighting, plate designs, dirt, reflections and camera optics are not
represented.

Dataset design note (recorded for honesty): the very first smoke run used 300×100
plates. On those, the detector's fixed 25×7 closing kernel could not bridge the gap
between the letter and digit groups and returned only the digit group. The base
plate was therefore reduced to 200×66 **before the full run**, and the 300×100 and
400×133 sizes were kept as explicit `distance` conditions so the effect is measured
rather than hidden. Ground truth was never touched.

## 2. Methodology

- Pipeline under test: `app.pipeline.service.process_image` — the exact function
  `POST /detect` and the Phase 11C camera runtime call. **No pipeline code was changed.**
- Stage timing wraps the detector and OCR entry points that `service.py` imports
  (`evaluation/run_ocr_eval.py::StageTimer`); the model is loaded once and the first
  inference (JIT/cache warm-up) is excluded from the per-image table.
- Metric definitions live in `evaluation/metrics.py` and are unit-tested
  (`tests/test_evaluation_metrics.py`, 6 tests):
  - *exact match* — normalised read equals ground truth; a NO_DETECTION / OCR_FAILED on a
    positive counts as **wrong**, never ignored;
  - *read CER* — Levenshtein(read, truth)/len(truth) over DETECTED positives;
    *end-to-end CER* additionally charges a miss as len(truth) deletions;
  - *false positive* — any plate reported on a negative image;
  - *trusted* — `ocrConfidence ≥ 0.5`, the API's `isPlateTrusted` boundary
    (`DEFAULT_OCR_CONFIDENCE_THRESHOLD`). A *trusted misread* is the case the backend would act on.
- Reproduce: `cd services/vision && python -m evaluation.dataset && python -m evaluation.run_ocr_eval`
  (writes `results/ocr_results.json` + `results/ocr_report.md`).

Confidence vs correctness (DETECTED positives):

| confidence bin | n | correct | accuracy |
|---|---:|---:|---:|
| [0.00, 0.50) | 26 | 6 | 23.1 % |
| [0.50, 0.70) | 112 | 85 | 75.9 % |
| [0.70, 0.90) | 230 | 199 | 86.5 % |
| [0.90, 1.00] | 698 | 600 | 86.0 % |

Interpretation: the 0.5 threshold removes a low-quality tail (23 % accurate) but
above it confidence is flat (≈86 %). 156 of 176 misreads carry confidence ≥ 0.5, and
135 of those 156 are **truncations** — the read is a correct *substring* of the plate
(e.g. `NXT7590` → `7590`) reported with high confidence. EasyOCR's confidence
describes the characters it read, not whether it read all of them, so confidence
cannot flag a partial read.

Error anatomy (176 misreads): 139 truncations/length errors (87 occlusion, 49
distance-near, 3 other), 11 equal-length substitutions (`0→O` ×5, `M→W` ×3, and one
each of `Z→7`, `P→4`, `I→9`, `5→I`, `9→5`, `8→9`, `4→8`), 26 mixed (mostly `blur_motion_9`).

## 6. Performance (measured, this host, CPU only)

Per-image inference, warm model (n = 1250, 800×600 frames):

| stage | mean | median | p95 | max |
|---|---:|---:|---:|---:|
| `process_image` total | 80.5 ms | 81.7 ms | 132.5 ms | 419.0 ms |
| detector (classical) | 4.9 ms | 4.8 ms | 5.8 ms | 9.6 ms |
| OCR (EasyOCR `readtext`) | 70.7 ms | 72.0 ms | 120.8 ms | 402.1 ms |

NO_DETECTION frames cost ≈ 9–10 ms (detector only). Live 1920×1080 webcam frames
(downscaled to 1600 px by `resize_if_needed`) cost 229–430 ms median (§8), i.e. the
2 fps `VISION_PROCESS_FPS` default is well within budget on this CPU, and a single
core-bound EasyOCR call, not the detector, dominates.

| … + delivery of `ZONE_OCCUPANCY_UPDATED` to an admin SSE subscriber | 40 | **391.0 ms** | 464.2 ms | 40/40 frames received, 0 missed |

`results/e2e_latency.json` (with `PARADA_API_URL=http://127.0.0.1:4100`).

**Finding — `localhost` costs 2 s per event.** With the default
`PARADA_API_URL=http://localhost:4100` (`results/e2e_latency_localhost.json`) the same
full chain measured **median 2428.9 ms, p95 2489.9 ms** (40 × 201). Diagnosis:
`localhost` resolves to `::1` first on this Windows host, the API binds `0.0.0.0`
(IPv4 only), and `app/api_client.py` opens a fresh `httpx.Client` per event, so every
event pays a ~2.2 s IPv6 connect failure before falling back to IPv4. With
`127.0.0.1` the per-event cost of the fresh client is still ≈ 250 ms above the
API's own 16 ms (connection setup per call). Not fixed in this phase (no behaviour
change was in scope); recorded for Phase 15 deployment config — set `PARADA_API_URL`
to an IPv4 literal or bind the API dual-stack, and consider a persistent client in
`api_client.py`.

## 10. Limitations

- **Synthetic only.** 50 plate texts in one font on a flat background. No real vehicle
  images, no reflections, dirt, shadows, plate frames, regional plate designs, or real
  optics. Real-world accuracy is unknown and **not** claimed.
- Sample size: 50 images per condition (95 % CI half-width ≈ ±14 pp at 50 %, ≈ ±5 pp at
  96 %); 100 negatives (a 0/100 FP result bounds the true rate below ≈ 3 % at 95 %).
- Conditions are applied one at a time; combined degradations (dark + blur + angle)
  were not tested.
- Physical camera evaluation is connectivity + live-frame false-positive behaviour
  only; no plate was shown to the cameras. RTSP untested on hardware.
- End-to-end latency is single-client, sequential, on one machine over loopback;
  no concurrency or scalability claim.
- The classical detector's operating envelope is narrow: plate widths of roughly
  150–300 px in an 800×600 frame; horizontal motion blur and >25 % occlusion defeat it
  or produce confident truncations that the confidence threshold cannot catch.

## 11. Accuracy conclusion

On this controlled synthetic set the Phase 11 pipeline reads **77.4 %** of plates
exactly (**93.8 %** character accuracy on detected plates) with **0/100** false
positives on no-plate scenes, and is essentially perfect (≥ 96 %) for clean, lighting,
sensor-noise, Gaussian-blur and moderate-angle conditions inside the detector's size
envelope. Its measured weaknesses are (1) plate scale outside ≈150–300 px, (2)
horizontal motion blur, and (3) partial occlusion / oversized plates producing
high-confidence *partial* reads. Because a partial read is still normalised into a
plate string, the backend's `ocrConfidence ≥ 0.5` trust rule does not protect against
it (AUROC 0.534); plate *length* / format validation would, and is recommended for a
later phase. Vision → API → DB → SSE takes ≈ 0.4 s per event on this host with an
IPv4 API URL, and ≈ 2.4 s with the default `localhost` URL.
